              Price Prediction Pipeline — 项目工程指南

一、整体架构图
================================================================================

  我们（Price 组）                                News 组
  ================                                =======

  yfinance 原始 OHLCV                             新闻文本
        │                                              │
        ▼                                              ▼
  ① fetch_data.py                                 GDELT / Finnhub 数据采集
        │                                              │
        ▼                                              ▼
  ② feature_engineering.py                        FinBERT 编码
     （不做归一化）                                      │
        │                                              ▼
        ▼                                         feat_news (FinBERT 特征向量)
  ③ dataset_builder.py                                 │
     构建滑动窗口 + 标签                                │
     所有特征合并为统一输入                              │
     按时间切分 train/val/test                          │
     仅用 train set 做归一化                            │
        │                                              │
        ├── X (30天窗口, 全部特征)                      │
        │      ─→ ④ lstm_model.py                      │
        │      ─→ ④ gru_model.py                       │
        │      ─→ ④ tcn_model.py                       │
        │                                              │
        │   3个模型各自输出:                              │
        │    · P(up) 分类概率                            │
        │    · feature vector 特征向量                   │
        │                                              │
        ▼                                              │
  ⑤ fusion_interface.py                                │
     导出所有特征向量 + metadata                         │
     打包成 fusion 层要求的格式                          │
                 │                                      │
                 └──────────────┬────────────────────────┘
                                ▼
                     Cross-Attention Fusion
                     （Price=Query, News=Key/Value）
                                │
                                ▼
                        Dual-Task 输出
                        ├── P(up)   分类（涨/跌）
                        └── r̂       回归（预测收益率）

二、执行顺序与阶段依赖
================================================================================

  阶段 A：数据准备（无任何模型参与）
  ──────────────────────────────
  ① fetch_data.py  →  ② feature_engineering.py  →  ③ dataset_builder.py
  完成后产出: train.npz / val.npz / test.npz（归一化后的监督学习样本）

  阶段 B：模型训练与评估（3个模型独立且可并行）
  ──────────────────────────────────────────
  ④ lstm_model.py      读取 train.npz → Bayesian超参搜索 → 训练 → 评估 → 保存
  ④ gru_model.py       同上
  ④ tcn_model.py       同上

  ⑤ metrics.py 被每个模型文件内部调用，计算 ROC-AUC / Accuracy / F1 等指标

  阶段 C：特征向量导出（为 Fusion 做准备）
  ──────────────────────────────────────
  ⑤ fusion_interface.py
     · 加载 3 个训练好的模型
     · 调用每个模型的 extract_features()
     · 把 3 组特征向量 + metadata 打包导出
     · 这一步的输出就是交给 News 组做 Fusion 的"接口文件"

  阶段 D：Fusion（与 News 组联合完成，不在我们 pipeline 内）
  ──────────────────────────────────────────────────────
  由 src/fusion/ 目录下的代码完成，不需要我们写


三、每个文件的职责
================================================================================

  fetch_data.py
  ─────────────
  通过 yfinance API 下载 20 只股票从 2018-01-01 至今的每日 OHLCV 数据。
  输出 data/raw/stock/all_stocks.csv，包含 Date, Ticker, Open, High, Low,
  Close, Adj Close, Volume 这些列。这是整个 pipeline 的起点。

  feature_engineering.py
  ──────────────────────
  读取 all_stocks.csv，对每个 ticker 独立计算两组特征：
    · 序列特征（12个）: 每日价格变化率、对数收益率、波动率等
    · 技术指标（27个）: SMA/EMA、RSI、MACD、布林带、ATR、动量等
  这两组特征在 dataset_builder 阶段会被合并为统一的输入。
  重要：这一步绝不做归一化，只输出原始特征值。
  输出 data/processed/stock/features/all_features.csv。

  dataset_builder.py
  ──────────────────
  读取 all_features.csv，完成以下工作：
    · 将序列特征和技术指标合并为统一的特征集（去重后约39个特征）
    · 对每个 ticker 构建 30 天的滑动窗口 → X (N, 30, num_features)
    · 生成二分类标签：明天收盘价 > 今天收盘价 = 1，否则 = 0
    · 全部样本按日期排序后，按 70%/15%/15% 做时间切分
    · 仅用 train set 计算 mean/std，再统一 apply 到 val 和 test
    · 保存 metadata（ticker, as_of_date, target_date）方便后续回溯
  输出到 data/processed/stock/dataset/：
    train.npz, val.npz, test.npz    → 包含 X, y
    train_meta.csv, val_meta.csv, test_meta.csv
    norm_stats.npz                   → 归一化参数（推理时复用）

  lstm_model.py
  ─────────────
  定义 LSTMClassifier 模型（PyTorch），内含两个模式：
    · forward(x) → P(up) 的 logit，用于分类训练
    · extract_features(x) → 分类头之前的隐藏向量，用于 Fusion
  训练流程全部封装在 train_lstm() 函数中：
    · 使用 Optuna 做 Bayesian 超参搜索（hidden_dim, layers, dropout, lr,
      batch_size, weight_decay, 激活函数）
    · 每个 trial 内部有 early stopping（监控 val ROC-AUC）
    · 搜索完成后用最佳参数重新训练 final model
    · 在 test set 上评估并保存 metrics
  额外提供 load / predict / extract_features 三个独立函数，
  供 fusion_interface.py 和后续步骤调用。
  输出: outputs/models/lstm_best.pt, outputs/metrics/lstm_metrics.json

  gru_model.py
  ────────────
  与 lstm_model.py 结构完全一致，区别是编码器换成 GRU。
  GRU 比 LSTM 更轻量、训练更快，作为 recurrent baseline。
  同样提供 forward() + extract_features() 双模式。

  tcn_model.py
  ────────────
  与 lstm_model.py 结构一致，但编码器换成 Temporal Convolutional Network。
  使用因果卷积 + 膨胀卷积来捕获长距离时间依赖，不依赖循环结构。
  同样提供 forward() + extract_features() 双模式。

  metrics.py
  ──────────
  所有模型共用的评估工具。不负责训练，只负责算分数。
    · compute_classification_metrics() → ROC-AUC, Accuracy, F1, Precision, Recall
    · save_metrics() / load_metrics()  → JSON 持久化
    · compare_model_metrics()          → 读取所有模型的 JSON，生成对比表

  fusion_interface.py
  ───────────────────
  这个文件不训练任何模型，它的职责是：
    · 加载已训练好的 3 个模型（LSTM, GRU, TCN）
    · 对 test set（或指定 split）的每个样本调用 extract_features()
    · 把 3 组特征向量导出为 .pt 或 .npy 文件
    · 同时导出一份 metadata CSV（ticker, as_of_date, target_date, 各模型的 P(up)）
  这份导出文件就是我们交给 Fusion 层 / News 组的"合同"。

  main_pipeline.py
  ────────────────
  唯一的执行入口，通过 bool 开关按顺序调用每一步：
    fetch → feature_engineering → dataset_builder → train_lstm → ...
  所有其他文件都不能独立运行，必须由 main_pipeline.py 统一调度。


四、统一特征输入设计
================================================================================

  X — shape: (N, 30, ~39)
  ──────
  过去 30 个交易日的所有特征组成的时间窗口，是一个三维张量。
  喂给 LSTM / GRU / TCN 这三个序列模型。

  这个统一输入合并了两组特征（去重后）：

  序列特征（来自 SEQUENCE_FEATURE_COLS）:
    对前日收盘的价格变化率（open/high/low/close）、对数成交量、
    日收益率、对数收益率、日内波幅、开收差、成交量变化率、
    20日均线偏离度、20日波动率比。

  技术指标（来自 TECH_INDICATOR_COLS）:
    SMA/EMA (5,10,20天)、价格相对均线偏离度、RSI-14、
    MACD 三件套、布林带 (宽度/%B)、ATR/ATR比率、
    10日动量、成交量比率。

  这两组特征被合并成统一的特征向量后，以 30 天窗口的形式输入模型。
  每个模型同时看到价格动态和技术指标在时间维度上的变化模式，
  能够学习到更丰富的时序表示。技术指标本身虽然已包含历史回看
  （如 RSI-14 回看 14 天），但将它们纳入时间窗口后，模型可以
  捕获"RSI 从超买区域回落"这类跨天的状态转换模式，这是单日快照
  无法提供的信息。


五、与 News 组的 Fusion 对接——我们需要准备什么
================================================================================

  Fusion 层（cross-attention + dual-task）不是我们写的，它在 src/fusion/ 里。
  但我们必须把"接口"准备好。具体来说，我们需要导出以下内容：

  1. 三组特征向量文件（对齐到同一批样本）
     · outputs/features/lstm_features.pt     shape (N, hidden_dim)
     · outputs/features/gru_features.pt      shape (N, hidden_dim)
     · outputs/features/tcn_features.pt      shape (N, hidden_dim)

  2. 一份 metadata CSV
     · outputs/predictions/price_model_outputs.csv
     · 包含: ticker, as_of_date, target_date, true_label,
            p_up_lstm, p_up_gru, p_up_tcn

  3. 对齐规则（必须与 News 组完全一致）
     · 预测目标: 下一个交易日的收盘价是否上涨（二分类）
     · 时间定义: as_of_date = 做出预测的那天 (day t)
                target_date = 被预测的那天 (day t+1)
     · 信息边界: 只能用 day t 及之前的信息，不能用未来数据

  News 组需要按同样的 (ticker, as_of_date, target_date) 对齐规则，
  输出一个 feat_news 特征向量。然后 Fusion 层会：
     · 把 [feat_lstm, feat_gru, feat_tcn] 拼接 → 线性投射
       → 完整的 price-side embedding → 作为 Query
     · feat_news → 作为 Key 和 Value
     · Cross-Attention → 残差连接 → LayerNorm → 融合表示
     · 分类头 → P(up)，回归头 → 预测收益率 r̂
     · 联合损失: L = 0.7 × L_cls + 0.3 × L_reg


六、单个模型的训练流程（以 LSTM 为例，GRU / TCN 完全相同）
================================================================================

  每个模型文件（如 lstm_model.py）的 train_lstm() 函数包含完整的三阶段流程：

  ┌─────────────────────────────────────────────────────────────┐
  │ 阶段 1：Bayesian 超参搜索（Optuna TPE, 默认 50 个 trial）     │
  │                                                              │
  │   搜索空间:                                                   │
  │     · hidden_dim    : [32, 64, 128, 256]                     │
  │     · num_layers    : [1, 2, 3]                              │
  │     · dropout       : [0.1 ~ 0.5]                            │
  │     · learning_rate : [1e-4 ~ 1e-2]  (对数刻度)              │
  │     · batch_size    : [64, 128, 256, 512]                    │
  │     · weight_decay  : [1e-6 ~ 1e-3]  (对数刻度)              │
  │     · activation    : [relu, gelu, silu]                     │
  │                                                              │
  │   每个 trial:                                                 │
  │     · 用采样出的超参数构建模型                                  │
  │     · 在 train set 上训练（最多 50 epochs）                   │
  │     · 每个 epoch 结束后在 val set 上算 ROC-AUC                │
  │     · early stopping: 如果 val ROC-AUC 连续 15 个 epoch       │
  │       不再提升，提前终止这个 trial                              │
  │     · MedianPruner: 如果表现低于其他 trial 的中位数，           │
  │       Optuna 直接砍掉这个 trial，节省时间                      │
  │     · 返回该 trial 的最佳 val ROC-AUC 给 Optuna               │
  │                                                              │
  │   50 个 trial 结束后，Optuna 选出 val ROC-AUC 最高的超参组合   │
  └──────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────┐
  │ 阶段 2：用最佳超参数重新训练 Final Model                       │
  │                                                              │
  │   · 用搜索出的最佳超参数创建新模型                              │
  │   · 在 train set 上训练（最多 200 epochs，比搜索时更长）        │
  │   · 同样有 early stopping（patience=15, 监控 val ROC-AUC）    │
  │   · EarlyStopping 内部始终保存当前最佳 epoch 的模型权重         │
  │   · 训练结束后恢复到那个最佳 epoch 的状态                       │
  │                                                              │
  │   保存:                                                       │
  │     outputs/models/lstm_best.pt           （模型权重+超参数）   │
  │     outputs/models/lstm_best_params.json  （超参数记录）        │
  └──────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
  ┌─────────────────────────────────────────────────────────────┐
  │ 阶段 3：在 test set 上做最终评估                               │
  │                                                              │
  │   · 调用 metrics.py 的 compute_classification_metrics()       │
  │   · 计算: ROC-AUC, Accuracy, F1, Precision, Recall           │
  │   · 生成 confusion matrix                                    │
  │                                                              │
  │   保存:                                                       │
  │     outputs/metrics/lstm_metrics.json     （完整评估报告）      │
  └─────────────────────────────────────────────────────────────┘

  关于 metrics.py 的调用时机:
    · 训练过程中（每个 epoch）: 只算 sklearn 的 roc_auc_score（轻量快速）
      用于 early stopping 判断和 Optuna 搜索方向
    · 训练完成后（仅一次）: 调用 metrics.py 的完整函数
      输出包含所有指标的 JSON 报告

  训练完成后如何复用模型（不需要重新训练）:
    · load_lstm_model(path)           → 加载已保存的最佳模型
    · predict_lstm(path, split)       → 用已保存模型做预测
    · extract_lstm_features(path)     → 用已保存模型提取特征向量给 Fusion
