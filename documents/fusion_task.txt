# Fusion Task

For collaboration with the news group and for the final system integration, the fusion module should operate on aligned feature representations rather than only on hard labels or scalar probabilities. 
The final design uses a cross-attention-based fusion layer combined with a dual-task output head. 
The key idea is that the price module and the news module should both output rich learned representations, which can then be deeply fused through attention instead of being combined by a simple weighted rule. 
On the price side, the final architecture contains three price encoders—LSTM, GRU, and TCN—and each encoder produces a learned feature vector for the same stock at the same prediction time. 
These three feature vectors are concatenated and projected through a linear layer into a shared price representation, forming the complete price-side embedding used by the fusion module.

From the price side, the final exported artifacts are organized under export_to_fusion/. 
The expected feature files are `features/lstm_features.pt`, `features/gru_features.pt`, and `features/tcn_features.pt`, while the prediction metadata file is `predictions/price_model_outputs.csv`. 
The CSV is expected to contain the alignment keys `ticker`, `as_of_date`, and `target_date`, the supervised label `true_label`, and the model probability columns `p_up_lstm`, `p_up_gru`, and `p_up_tcn`. 
These fields define the contract between the price module and the fusion module. 
The most important requirement is that every price-side feature row and every news-side feature row must refer to the exact same stock, the exact same prediction timestamp, and the exact same future target day. 
No future information may be used on either side beyond `as_of_date`.

Under this interface, the fusion layer should first construct the complete price-side embedding from the three price encoders. 
That means concatenating the LSTM, GRU, and TCN feature vectors for the same aligned sample, and then projecting the concatenated representation through a linear layer into a shared price representation space. 
On the news side, the news module should provide a feature vector extracted from FinBERT or another chosen news encoder, using the same alignment key `(ticker, as_of_date, target_date)`. 
The fusion layer then applies cross-attention, where the price-side embedding acts as the Query and the news-side embedding acts as the Key and Value. 
This allows the model to condition news selection on the current price context rather than treating every piece of news information equally.

After cross-attention, the fused representation should pass through a residual connection and LayerNorm before entering the output heads. 
The final output design uses a dual-task objective. 
One head performs binary classification and predicts the final upward-movement probability P(up). 
The other head performs regression and predicts the next-day return r̂. 
The classification objective can be trained with binary cross-entropy style loss, while the regression objective can be trained with Huber loss or another robust regression loss. 
The total fusion objective can be written as a weighted joint loss, for example L = α × L_cls + (1 − α) × L_reg with α = 0.7 as a default starting point. 
This dual-task design is useful because the classification head focuses on directional accuracy while the regression head encourages the shared fused representation to preserve magnitude information.

From the perspective of collaboration, the external interface matters more than the internal architecture details of either side. 
The price group and the news group do not need to share the same encoder type, but they must share the same sample alignment rule and target definition. 
That means both sides must agree on three things: first, they are predicting the same stock; second, they are making the prediction at the same time point `as_of_date`; third, they are predicting the same future target date `target_date`. 
In addition, both sides should export dense feature vectors rather than only final labels, because the cross-attention layer requires learned representations as inputs. 
The probability columns from the price side are still useful and should be preserved as auxiliary signals or for later analysis, but they are not a substitute for the encoder feature vectors themselves.

In summary, the fusion task is to merge aligned price-side and news-side representations under a shared temporal contract. 
The final practical interface on the price side consists of LSTM, GRU, and TCN hidden representations plus the metadata-and-probability CSV. 
The fusion module should therefore be written to consume the exported LSTM, GRU, and TCN features directly under the same naming and alignment scheme. 
As long as the fusion layer preserves the alignment contract and treats the exported hidden vectors as the primary price-side representation, the overall design remains correct and fully compatible with the final price_prediction_pipeline.

## Cross-Attention Fusion and Dual-Task Output Detail

Cross-attention is the intended final fusion mechanism because it is more expressive than a simple linear or weighted combination of modalities. 
For each aligned sample, the fusion input from the price module consists of three hidden representations: one from the LSTM encoder, one from the GRU encoder, and one from the TCN encoder. 
These vectors are stored separately in `lstm_features.pt`, `gru_features.pt`, and `tcn_features.pt`, while `price_model_outputs.csv` stores the row-wise alignment information and the scalar probabilities `p_up_lstm`, `p_up_gru`, and `p_up_tcn`. 
The recommended implementation flow is therefore: first, load the metadata CSV; second, join it with the corresponding news-side feature table using `(ticker, as_of_date, target_date)` as the key; third, load the aligned LSTM, GRU, and TCN hidden vectors in the same row order; fourth, concatenate those price vectors and project them into a shared price embedding; and finally, apply cross-attention between the projected price embedding and the aligned news embedding.

The dual-task design remains an important part of the final system. 
After cross-attention, the fused representation feeds into a classification head that predicts the final probability of upward movement and a regression head that predicts the next-day return. 
The classification head focuses on the directional decision boundary, while the regression head encourages the fused representation to preserve magnitude information. 
Together, these two objectives provide complementary gradient signals and support a stronger shared representation than a single-output setup. 
Under this design, the fusion module is not merely combining three price probabilities with a news score; it is learning a true joint representation from three price-side embeddings and one news-side embedding under a shared temporal contract.

在与 news 组协作以及最终系统集成时，fusion 模块不应该只依赖硬标签或单个标量概率，而应该工作在时间对齐后的特征表示上。最终设计采用 
cross-attention 融合层加 dual-task 输出头。这里的核心思想是，price 模块和 news 模块都应该输出丰富的 learned representation，
然后通过 attention 机制做深度融合，而不是只靠简单加权规则拼接结果。对于 price side，最终架构包含三个 price encoders，也就是 LSTM、GRU 和 TCN，
并且每一个 encoder 都会在同一个股票、同一个预测时刻上输出一份 learned feature vector。这三份特征向量会先拼接，再通过线性层投射到共享的 price 
representation space 中，形成 fusion 模块使用的完整 price-side embedding。

从 price side 看，最终导出产物会放在 export_to_fusion/ 目录下。预期的特征文件包括 `features/lstm_features.pt`、`features/gru_features.pt` 
和 `features/tcn_features.pt`，预测与 metadata 文件是 `predictions/price_model_outputs.csv`。这个 CSV 预期包含对齐键 `ticker`、`as_of_date`、
`target_date`，监督标签 `true_label`，以及模型概率列 `p_up_lstm`、`p_up_gru` 和 `p_up_tcn`。这些字段共同构成 price 模块和 fusion 模块之间的合同。
最重要的要求是：每一行 price-side 特征和每一行 news-side 特征都必须对应到完全相同的股票、完全相同的预测时刻，以及完全相同的未来目标日。双方都不能在 
`as_of_date` 之后使用任何未来信息。

在这个接口下，fusion 层首先需要基于三个 price encoders 构造完整的 price-side embedding。也就是说，对于同一个对齐样本，要把 LSTM、GRU 和 TCN 
三份特征向量拼接起来，再通过线性层投射到共享的 price representation space 中。news side 则应当在同样的 `(ticker, as_of_date, target_date)` 
对齐规则下，输出一个由 FinBERT 或其他新闻编码器提取的特征向量。随后，fusion 层使用 cross-attention，其中 price-side embedding 作为 Query，
news-side embedding 作为 Key 和 Value。这样模型就可以让价格上下文去有条件地选择最相关的新闻信息，而不是把所有新闻信号等权看待。

经过 cross-attention 之后，融合表示需要先通过残差连接和 LayerNorm，再送入输出头。最终输出设计采用 dual-task。一个头做二分类，预测最终的上涨
概率 P(up)；另一个头做回归，预测下一交易日收益率。分类目标可以用 binary cross-entropy 类损失训练，回归目标可以用 Huber loss 或其他更鲁棒的回归损失。
总的融合目标可以写成加权联合损失，例如 L = α × L_cls + (1 − α) × L_reg，默认可从 α = 0.7 开始。这样的 dual-task 设计之所以重要，是因为分类头更关注方向
判断，而回归头会促使共享融合表示保留收益率幅度信息。

从团队协作的角度看，真正重要的是外部接口，而不是双方内部编码器的具体结构。price 组和 news 组不需要使用相同类型的编码器，但必须共享相同的样本对齐规则和
目标定义。也就是说，双方必须统一三件事：第一，预测的是同一只股票；第二，做出预测的时刻是同一个 `as_of_date`；第三，被预测的未来日期是同一个 `target_date`。
另外，双方都应该导出稠密特征向量，而不是只给最终标签，因为 cross-attention 需要以 learned representation 作为输入。price side 导出的概率列依然有价值，
可以保留为辅助信号或后续分析字段，但它们不能替代 encoder feature vector 本身。

总结来说，fusion task 的本质是在统一时间合同下，把对齐后的 price-side 表示和 news-side 表示融合起来。最终在 price side 上，实际接口应当由 LSTM、GRU 和 TCN 
三组隐藏表示，以及配套的 metadata + probability CSV 构成。因此，fusion 模块应当直接消费导出的 LSTM、GRU 和 TCN 特征，并在同一命名规则和对齐规则下工作。
只要 fusion 层遵守这一对齐合同，并把这些导出的 hidden vectors 当作主要的 price-side representation，整体设计就是正确的，并且与最终的 
price_prediction_pipeline 完全兼容。

## Cross-Attention 融合与 Dual-Task 输出细节

Cross-attention 被选作最终融合机制，是因为它比简单的线性拼接或加权融合更有表达力。对于每一个对齐样本，来自 price 模块的融合输入包含三份隐藏表示：
一份来自 LSTM 编码器，一份来自 GRU 编码器，一份来自 TCN 编码器。这三个向量分别保存在 `lstm_features.pt`、`gru_features.pt` 和 `tcn_features.pt` 中，
而 `price_model_outputs.csv` 则保存逐行对齐所需的 metadata，以及标量概率 `p_up_lstm`、`p_up_gru` 和 `p_up_tcn`。因此，一个推荐的实现流程是：先加载 
metadata CSV；再使用 `(ticker, as_of_date, target_date)` 作为键，与 news-side 特征表对齐；然后按同样的行顺序加载 LSTM、GRU 和 TCN 的隐藏向量；
接着把这三组 price 向量拼接并投射成共享的 price embedding；最后在这个投射后的 price embedding 和 news embedding 之间应用 cross-attention。

dual-task 设计仍然是最终系统的重要组成部分。经过 cross-attention 后，融合表示会同时送入一个分类头去预测最终上涨概率，以及一个回归头去预测下一交易日收益率。
分类头强调方向判断的决策边界，而回归头鼓励融合表示保留幅度信息。这两个目标一起提供互补的梯度信号，使得共享表示比单一输出设置更强。在这个设计下，fusion 模块
并不是简单地把三个 price 概率和一个 news 分数拼起来，而是在统一时间合同下，从三组 price-side embedding 和一组 news-side embedding 中学习真正的联合表示。
